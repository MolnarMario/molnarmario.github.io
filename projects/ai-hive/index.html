AI Hive

I built it when one terminal per assistant stopped scaling, somewhere around the fifth project. It lets me keep several workstreams moving at once and see all of them in one place.

Source on GitHub ↗ Changelog

What it does

  1. Many agents, real terminals, one window. Each tile is a Windows pseudo-console (ConPTY) running Claude Code, Gemini, Grok or a plain shell, so every CLI behaves exactly as it does on its own. Grids go from 1×1 to 4×3.
  2. Agents that don't trip over each other. Agents in a workspace share an activity board through an MCP server. Before one edits a file, it can see that another agent already claimed it.
  3. Work keeps running when you look away. Each workspace maps to a project folder and keeps executing while hidden. Its sidebar badge stays green while agents are healthy and pulses amber while one is working.
  4. Waits out usage limits for you. It reads plan usage from the CLI into the top bar. When a limit runs out it can wait for the reset and resume the agents on its own.
  5. See what each agent is doing at a glance. Every agent row shows its task, or Claude Code's own conversation title read live from the transcript, so you don't have to read its terminal.
  6. Per-agent model, effort and mode. Dropdowns map to the real CLI flags. The card header follows whatever you change inside the terminal, and the permission mode survives a restart.
  7. A sidebar you can organize. Drag agents and workspaces to reorder them, and group workspaces into collapsible categories. The layout persists across restarts.

How it was built

I started AI Hive on 5 July 2026, when I was running more coding agents than I could follow in separate terminal windows. Since then it has been built by the agents it runs: they take tasks, coordinate on the shared board and ship through pull requests, and every release gets a numbered changelog entry.

Decisions that mattered

  • Session data is never only in memory. Adding or removing an agent saves at once, saves are atomic (a temp file, then a rename) and a failed load keeps the old file as a backup instead of deleting it. Each rule has a regression test, and the README traces several of them to sessions where agents were lost.
  • One copy at a time, enforced by Windows. A named mutex refuses a second launch, so two copies can never overwrite each other's session file.
  • Closing a card kills everything it started. Each card's processes run in a Windows Job Object, so a shell's grandchildren die with it, even if the app itself crashes.
  • Agents work in lanes. An agent can get its own git worktree. It flags finished work with a "Task done" commit, and an integrator agent merges a batch through one pull request once a GPT-6-Luna review comes back clean.

How it's tested

A smoke suite of 4,159 checks drives the real app headlessly, with real child processes, in up to six parallel workers. One end-to-end test talks to a live Claude Code agent, closes the app, reopens it and checks that the same conversation comes back on the same card, which is exactly where data used to get lost.

Where it stands

In daily use. I run my projects from it, this site included.
