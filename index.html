02 / Process

How I build with agents

Agents write most of the code. Deciding what to build, reviewing it and finding where it breaks is still my job, and it's the part that decides whether the thing is any good.

  1. 1

    Write the spec first

    Every project starts as a plan file: what it does, what it won't do, how I'll know it works. The expense tracker's spec had numbered acceptance scenarios before any code existed.

  2. 2

    Run agents in parallel

    Several agents per project, each on its own task, coordinating through a shared board in AI Hive so two of them don't rewrite the same file.

  3. 3

    Test like it's my day job

    Because it is. Unit tests for the maths, end-to-end tests for the flows, and an adversarial review pass before anything merges. The expense tracker ships with 116 unit tests.

  4. 4

    Ship something you can open

    A link that plays, an APK that installs, an extension that loads. If it only runs on my machine, it isn't done.

03 / About

Hi, I'm Mario.

I've spent eleven years on the web, most of them at Thrive Themes. I did six years of technical support, debugging WordPress sites across the whole stack, then moved to QA in 2023. These days I write Playwright suites covering nine Thrive products and WordPress core. Before all that I built scrapers for car listings at AutoUncle.

More than a decade of meetings and working across teams taught me how software should be built, and plenty about how it shouldn't. My degree in electronics and telecommunications adds an engineer's view. I want to know how a thing works, and where it breaks, before I trust it. Support filled in the other half. Six years of tickets from people whose site had just gone down taught me how customers think, and I still think like one before I build anything. The first question I ask is what someone will try when they open it cold.

Testing taught me how software fails. AI agents let me build software fast enough to find out. The two fit together better than I expected: agents are quick and confident and wrong in interesting ways, and catching that is exactly what a QA engineer does.
